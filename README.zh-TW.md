# SqlLookout

[English](README.md) | 繁體中文

SQL Server 監控工具。開發中:版本 0.9.x,可能還有粗糙之處。

它用唯讀登入,從一台機器連到你的 SQL Server 執行個體,不在被監控的伺服器上安裝任何東西。
設定在網頁上完成。歷史資料存在本機的 SQLite 檔案,有事需要處理時寄 email(需要的話也可發 Teams 訊息)。

SQL Server 是 Microsoft Corporation 的商標。本專案與 Microsoft 無關,也未經其背書。

## 快速開始(網頁介面)

1. 在每台 SQL Server 上,以 sysadmin 執行 `sql/create-readonly-login.sql`(先改檔案開頭的名稱和密碼)。
   這個登入只能讀中繼資料和統計資訊:不能讀資料表內容,也不能寫入。
2. 在監控用的機器上解壓縮並執行,先試用看看(要常駐成 Windows 服務,見下方「安裝成 Windows 服務」):

```
sqllookout.exe web
```

3. **在那台機器上**開啟 `https://localhost:8443/`。瀏覽器會警告憑證(憑證是第一次啟動時自行簽發的);
   繼續前往即可,或用 `--cert` 換成你自己的憑證。建立管理員帳號(這一步只能從本機做,所以網路上其他人無法搶先建立)。
4. **Servers > Add a server**,填入名稱和登入資訊,按 **Test**。每項檢查會顯示「works」,或告訴你缺哪個權限。
   一分鐘內 **Dashboard** 就會出現資料。
5. **Settings**:郵件伺服器和收件人、Teams、安靜時段、每日摘要、各項上限。變更立即生效。

**語言:** 網頁和警示郵件有英文與繁體中文。可在第一次設定頁選擇,之後隨時用每頁右上角的按鈕切換,
或到 Settings > General。(無頭模式:JSON 檔裡設 `"language": "zh-TW"`。)

選項:`--port 8443`、`--listen 0.0.0.0`(`127.0.0.1` 表示只允許本機)、`--data <資料夾>`
(歷史與設定;預設為程式旁的 `data`)、`--cert <pfx> --cert-password-file <檔案>`。

### 安裝成 Windows 服務

**用精靈:** 在解壓縮的資料夾雙擊 `Setup.cmd`(或執行 `sqllookout.exe setup`)。瀏覽器會開啟設定頁:選資料夾、連接埠、
誰可以開啟網頁、服務帳號,以及歷史資料放哪裡(檔案,或 SQL Server 資料庫,附「測試連線」按鈕),然後按 **Install**。
這時 Windows 才會要求系統管理員權限;精靈本身不以系統管理員執行,只在本機監聽,位址只有它開啟的那個分頁知道。
SqlLookout 已安裝時,同一頁會提供 **Upgrade**(從你解壓縮的新資料夾升級)和 **Uninstall**。有英文和繁體中文。
它執行的就是下面的指令,所以指令做什麼,精靈就做什麼。

**用命令列:** `sqllookout.exe web` 在關閉視窗或登出時就會停止。要讓它持續執行,請在解壓縮的資料夾以**系統管理員**開啟命令提示字元,執行:

```
sqllookout.exe install
```

它會把程式複製到 `C:\Program Files\SqlLookout`,資料放在 `C:\ProgramData\SqlLookout`(只有 Administrators、SYSTEM 和服務帳號可讀,
因為任何能讀該資料夾的人都能解密儲存的密碼),建立隨 Windows 啟動、當機後自動重啟的服務,開啟防火牆連接埠,
並等到網頁有回應。選項:`--dir`、`--data`、`--port`、`--listen`(用 `127.0.0.1` 則不加防火牆規則)、
`--cert` 與 `--cert-password-file`、`--no-firewall`。

原本在視窗裡執行?帶上它用的資料夾,資料才不會遺失:`sqllookout.exe install --data <原本的資料夾>`。

對 Windows 驗證的伺服器,服務會以它執行的帳號登入:預設是 LocalSystem,SQL Server 看到的是電腦帳號(`DOMAIN\MACHINE$`)。
要改用網域帳號,加上 `--account DOMAIN\name --password-file <第一行為密碼的檔案>`(受管理服務帳號,名稱以 `$` 結尾,不需要密碼檔)。
該帳號需要「以服務方式登入」的權限。

**升級:** 把新版解壓縮到任何位置,在該資料夾開系統管理員命令提示字元,執行 `sqllookout.exe upgrade`。
它會停止服務,把舊程式檔存到 `C:\Program Files\SqlLookout.prev`,複製新檔案,啟動服務並確認網頁有回應。
資料資料夾不會被動到。如果新版無法啟動或沒有回應,會放回舊檔案並重新啟動。比已安裝版本舊的版本會被拒絕。

**解除安裝:** `sqllookout.exe uninstall` 會移除服務和防火牆規則,並保留資料;加上 `--delete-data` 連資料一起刪除。
程式資料夾留給你自己刪。

### 把歷史與設定放在 SQL Server(選用)

預設情況下,歷史、警示、伺服器清單和登入帳號都存在資料資料夾裡的 SQLite 檔案。
要改存在 SQL Server 資料庫:先在要存放的伺服器上執行一次 `sql/create-store-database.sql`
(它會建立專屬資料庫和一個對該資料庫有 `db_owner` 的登入),把連線字串寫在文字檔的第一行,然後帶著它啟動:

```
sqllookout.exe install --store-connection-file C:\temp\store.txt
```

`install` 會連線、確認該登入可以建立資料表、拒絕 `master` 這類系統資料庫,並把連線字串用 Windows DPAPI 保護後存進資料資料夾;
之後可以刪掉明文檔案。不用 `install` 時,`sqllookout.exe web --store-connection-file <檔案>` 對一直開著的視窗做同樣的事,
`reset-password` 和 `mcp` 也接受同一個選項。資料表會在第一次啟動時建在該資料庫裡。

* **不會搬移舊資料。** 切換時不會複製 SQLite 檔案裡已有的內容:新資料庫是空的,所以要重新加入伺服器和管理員,歷史從那天重新開始。舊檔案原地保留。
* **一個資料庫只給一個 SqlLookout。** 兩個程式寫入同一個資料庫,每個警示都會發兩次。儲存的 SQL 密碼是為儲存它的那台機器加密的,
  所以把服務搬到另一台電腦時要重新輸入。
* **放哪裡。** 最好用不在被監控名單內的伺服器,否則那台伺服器出事時,歷史資料也一起消失。
* **仍留在資料資料夾的:** 憑證、登入金鑰和診斷記錄。
* **無頭模式**(`run`、`run-once`、`status` 搭配 JSON 檔)繼續使用 SQLite。
* 程式每次使用前會檢查連線,網路中斷或伺服器重啟後會重新連線。
* 用 store 檔開啟的 MCP 伺服器只能讀:程式會拒絕該連線上的所有寫入。要再加一層保護,只給它的登入 `db_datareader`。

## 看懂各頁面

* **Dashboard**:每台伺服器一行,最嚴重的在前(連不上、嚴重、警告、正常、暫停),附問題數量、六小時 CPU 線、最低的磁碟剩餘 %、
  最舊的完整備份和失敗的工作數。表格下方是目前所有問題的簡短清單(前 20 筆;其餘在各伺服器自己的頁面)。
* **伺服器頁面**(點名稱):分頁有 **Problems**、**Databases**(最先需要看的)、**Disks**(表格和剩餘空間圖)、
  **SQL Agent jobs**(在你按「Show all」之前只列失敗、取消或執行中的工作)、**Performance**(CPU、記憶體、頁面預期壽命、連線數、
  阻塞、磁碟 I/O 延遲、死結)以及 **Queries**。圖表涵蓋 6 小時、24 小時、7 天或 30 天;長區間抽稀時會保留短暫的尖峰。
  Queries 分頁在開啟時即時讀取伺服器(不儲存任何東西,頁面也不會自動重新整理):顯示目前正在執行的使用者查詢,
  含目前的陳述式、等待和阻塞者,以及計畫快取中最耗資源的 15 個陳述式。查詢文字可能含有資料,所以只顯示給已登入的使用者。需要 VIEW SERVER STATE。
* 圖表由伺服器畫成純 SVG:頁面仍然不含任何 JavaScript。
* **佈景主題:** 標題列的按鈕循環切換 Auto(跟隨瀏覽器或 Windows)、Light 和 Dark。選擇只存在該瀏覽器的 cookie,所以每個人可以選自己的。
* **外觀:** 在 Settings > General 選 **Classic**(原本的樣式,也是預設)或 **Terminal**。整個安裝共用一個選擇,立即生效,登入頁也一樣。
  Terminal 是緊湊、直角、等寬字型的風格;狀態除了顏色,一律也用文字或符號標示。它使用電腦上已有的字型
  (有裝 IBM Plex Mono 就用,否則用 Consolas 或系統等寬字型),因為頁面不會從網際網路載入任何東西。更新不會改變既有安裝的外觀。
  (無頭模式:JSON 檔裡設 `"look": "terminal"`。)

| 檢查 | 何時警示 |
|---|---|
| 最後一次完整備份 | 超過 26 小時(警告)/ 48 小時或沒有(嚴重);每個執行個體一則警示,列出資料庫,嚴重的在前(最多 20 個) |
| 最後一次成功的 DBCC CHECKDB | 超過 8 天 / 15 天,或從未執行;每個執行個體一則警示,列法相同 |
| Suspect pages | 任何未修復的頁面 |
| 資料庫狀態 | SUSPECT、OFFLINE、EMERGENCY、RECOVERY_PENDING |
| 磁碟剩餘空間 | 低於 20% 或 10 GB(警告)/ 10% 或 5 GB(嚴重) |
| 磁碟減少速度 | 依近期趨勢,4 小時內(警告)/ 1 小時內(嚴重)會把磁碟區填滿 |
| 記錄檔使用量 | 超過 80% / 90%(小於 100 MB 的記錄檔忽略);每個執行個體一則警示,列出資料庫,最嚴重的在前(最多 20 個) |
| 檔案大小 | 記錄供歷史查詢,不警示 |
| SQL Agent 工作 | 上次執行失敗(嚴重),執行時間超過平均的 2 倍(警告) |
| CPU | 機器 CPU 連續 10 分鐘在 90% 以上(警告) |
| 阻塞 | 某個工作階段被阻塞 60 秒以上(警告)/ 300 秒以上(嚴重);指出最上游的阻塞者 |
| 頁面預期壽命 | 連續 10 分鐘每次檢查都低於 300 秒(警告) |
| 記憶體授予 | 連續 5 分鐘每次檢查都至少有一個查詢在等記憶體授予(警告) |
| 死結 | 最近一小時 3 次以上(警告)/ 20 次以上(嚴重) |
| 連線數 | 使用者連線數連續 5 分鐘每次檢查都達 500(警告)/ 1500(嚴重) |
| 磁碟 I/O 延遲 | 整個執行個體的平均讀或寫延遲連續 15 分鐘每次檢查都達 50 ms(警告)/ 150 ms(嚴重) |
| 最主要的等待 | 記錄供歷史與 MCP 伺服器使用,不警示 |
| 可用性群組 | 複本中斷或不健康,或資料庫的資料移動暫停或不健康(嚴重);部分健康為警告。每個執行個體一則警示,列出有問題的項目。需要 SQL Server 2012 以上且啟用 Always On;次要複本只看得到自己,所以也要加入主要複本 |
| 記錄傳送 | 最後一次記錄備份或還原超過記錄傳送本身設定的上限(警告)/ 該上限的 2 倍(嚴重,`LogShippingCriticalMultiplier`);從未執行的工作為警告。設定中警示已關閉的配對會略過。每個執行個體一則警示 |
| 資料庫鏡像 | 被鏡像的資料庫暫停或中斷(嚴重),見證中斷(警告)。每個執行個體一則警示 |
| Express 容量上限 | 僅限 SQL Server Express:資料檔達到該版本上限的 80%(警告)/ 95%(嚴重)(10 GB;2008 以前為 4 GB;SQL Server 2025 為 50 GB);記錄檔和 tempdb 不計。每個執行個體一則警示,列出資料庫 |
| tempdb 空間 | tempdb 資料檔 80%(警告)/ 95%(嚴重)已滿,以它能達到的空間衡量(目前大小加上允許的成長,受 max_size 和磁碟區剩餘空間限制)。警示會顯示使用者 / 內部 / 版本存放區的用量和最大的工作階段。如果無限成長出現在太舊、無法回報磁碟區空間的伺服器上,則不判斷 |
| 登入失敗 | 最近 15 分鐘內 10 次以上登入失敗(警告),50 次以上(嚴重),由目前的 SQL Server 錯誤記錄計算(錯誤 18456)。警示會列出最頻繁的登入名稱和來源用戶端位址。需要 sysadmin 或 `master.dbo.xp_readerrorlog` 的 EXECUTE;如果伺服器不稽核失敗的登入,則什麼都不顯示 |
| 連線可達性 | 連續 2 次連線失敗(警告)/ 3 次(嚴重) |
| 收集器本身 | 某項檢查連續 3 次失敗或被拒絕 |

問題消失後,要持續消失 30 分鐘才算解決(JSON 設定的 `ResolveAfterMinutes`,0 = 立即),
所以在上限附近來回的數值不會每次擺盪都寄出新的和已解決的郵件。

沒人管的測試和暫存資料庫可以排除:編輯伺服器,在「Databases to ignore」下列出名稱(一行一個;`*` 代表任意文字,例如 `SqlLookoutAge_*`)。
它們會被備份、CHECKDB、記錄檔、狀態、suspect page、記錄傳送、鏡像和可用性群組資料庫的警示以及 Dashboard 的最舊備份欄略過,但仍會顯示在 Databases 分頁。

每台伺服器可以有自己的門檻:編輯伺服器,在「Thresholds for this server only」下列出,一行一個,例如 `DiskWarnFreePercent = 15` 或 `FailedLoginWarnCount = 100`
(名稱就是設定檔 `thresholds` 區段的名稱,不分大小寫;在 JSON 設定檔中,於該執行個體上使用 `"thresholdOverrides": { "DiskWarnFreePercent": 15 }`)。
沒列出的使用 Settings 裡的共用值。結果仍須合理(警告等級低於嚴重等級),否則會拒絕儲存。

**Teams:** Settings > Teams alerts 會把同樣的警示發到 Teams 聊天或頻道,可單獨使用或與 email 並用。在 Teams 中建立一個 Workflows 流程,
觸發條件選「收到 Teams webhook 要求時」,動作選「在聊天或頻道中張貼卡片」,貼上它給你的位址(含密鑰的 https 位址,所以會加密儲存,不再顯示)。
舊式的 incoming-webhook 連接器位址也可以用。在 Teams 中,聊天至少要有兩位成員,流程才能張貼進去。儲存後按「Send a test Teams message」。
email 和 Teams 都開啟而其中一個失敗時,另一個仍會通知你,失敗也會寫入記錄;只有所有管道都失敗時,才會在下一次檢查重試。
無頭模式:在 `alerts` 下設 `"teams": { "urlEnv": "變數名稱" }` 或 `"urlFile": "路徑"`。

已經知道的問題可以從伺服器 Problems 分頁中的那一列靜音:「Acknowledge until it is gone」,或暫停 1 小時、4 小時、1 天或 7 天。靜音期間不寄信
(Dashboard 會標示,每日摘要仍會列出並附註)。暫停到期、情況惡化(警告變嚴重)、或消失後又出現時,它會再次通知;「Turn alerts back on」立即結束靜音。
靜音的問題解除時,仍會寄出一般的已解決郵件。

每個上限都可以在 Settings 頁面修改,每個警示群組也可以關閉。支援 SQL Server 2008 以後;支援 Express(其上沒有 Agent 檢查)。

一個問題會寄一次,在它持續存在期間按重複間隔再寄,惡化時立即寄,解除時再寄一次。每日摘要郵件同時也是「服務還活著嗎」的檢查:
如果它不再寄來,表示服務停了。

## 安全性

* 只有 HTTPS,不存在純 HTTP 連接埠。
* 使用本機帳號登入;密碼以 PBKDF2 雜湊儲存;連續 5 次輸入錯誤會鎖定帳號 5 分鐘(被鎖的帳號回應方式與不存在的使用者相同,所以頁面不會洩漏哪些使用者名稱存在)。
  登出或變更密碼會終結所有較早的工作階段,即使 cookie 已被複製。
* 忘記密碼要在機器本身重設,不在網頁上(沒有「忘記密碼」連結):執行 `sqllookout reset-password --data <資料夾>`(有多個帳號時加 `--user <名稱>`)。
  它會問兩次新密碼,或在管線輸入時從標準輸入讀一行。它會讓所有人登出並解除鎖定,網頁介面執行中也能用。
* SQL 密碼、SMTP 密碼和 Teams webhook 位址以 Windows DPAPI(電腦範圍)加密儲存,不再顯示。
  這可以在資料檔被複製到另一台機器時保護它。**在監控機器本身上,任何能讀資料資料夾的本機使用者都能解密它們**,
  所以請把該資料夾(`--data` 資料夾,預設為程式旁的 `data`)限制為只有 Administrators、SYSTEM 和服務執行帳號。`sqllookout install` 會對資料資料夾做這件事。
* 保護登入 cookie 和表單權杖的金鑰存在 `data\keys`(同樣以 DPAPI 加密)。
* 頁面不含 JavaScript,內容安全政策也禁止它。表單帶有防偽造權杖。
* 連線錯誤只顯示 SQL 錯誤編號,不顯示文字,因為文字可能重複連線字串。
* 監控登入是唯讀的。SqlLookout 絕不寫入你的 SQL Server。
* 遠端 MCP 端點(`/mcp`)在建立金鑰之前是關閉的,只接受會過期的 `Authorization: Bearer` 金鑰,且唯讀;見 MCP 一節。

## 舊伺服器(2008 / 2008 R2)

* 如果連不上伺服器,編輯它並選 **No encryption**(舊伺服器常無法協商現代 TLS)。
* 磁碟檢查需要 2008 R2 SP1 或更新;更舊的版本會略過,顯示為「not available」而不是錯誤。
* 2016 SP2 以前,只有 sysadmin 能讀最後一次成功的 CHECKDB 時間。用唯讀登入時,這些資料庫顯示「unknown」,也不會警示。

## 無頭模式(沒有網頁)

設定改放在 JSON 檔(`sqllookout.example.json`):

```
sqllookout check-config    # 驗證檔案並測試每個連線
sqllookout run-once        # 收集一次,不寄信,印出找到的內容
sqllookout status          # 再印一次已儲存的結果,不收集
sqllookout run             # 收集並警示,直到停止
```

此檔案中帶密碼的連線字串會被拒絕;請用 `connectionStringFile` 或 `connectionStringEnv`。

## MCP 伺服器(給 AI 助理)

```
sqllookout mcp --data <資料夾>      # 與 'sqllookout web' 相同的資料資料夾
```

透過 stdio 的唯讀 MCP 伺服器。它以 SQLite 唯讀模式開啟歷史檔,所以無法改動監控記錄的任何內容,也不會連到你的 SQL Server。
工具:`list_instances`、`get_problems`、`get_overview`、`get_metric_history`。回答中的名稱(資料庫、工作、登入)來自被監控的伺服器,屬於不受信任的文字。
用戶端設定範例:

```json
{ "mcpServers": { "sqllookout": { "command": "C:\\SqlLookout\\sqllookout.exe", "args": ["mcp", "--data", "C:\\SqlLookout\\data"] } } }
```

執行用戶端的帳號需要有資料資料夾的讀取權限;使用期間監控會繼續執行。

### 從另一台電腦(https,使用金鑰)

`sqllookout web` 也在 `https://<這台機器>:<連接埠>/mcp` 回應 MCP,所以另一台電腦上的助理不需要存取資料資料夾就能使用。

1. 在網頁介面開啟 **Settings > MCP access keys** 建立金鑰。給它名稱、有效期限(30、90 或 365 天),以及全部伺服器或它可以看到的伺服器。
   **金鑰只顯示一次**;只保存雜湊。
2. 把它加到用戶端,例如在 Claude Code:

   ```
   claude mcp add --transport http sqllookout https://monitor.example:8443/mcp --header "Authorization: Bearer slk_..."
   ```

* 在第一把金鑰出現之前,`/mcp` 回應 404,彷彿不存在。缺少、錯誤、過期或已撤銷的金鑰都得到相同的 401。
  同一位址在 5 分鐘內送出 10 把不存在的金鑰(IPv6 位址以其 /64 網路計),該位址會被拒絕 5 分鐘;重新啟動會清除。
  沒有標頭、或金鑰已過期或撤銷的要求不計入,所以不會鎖住同一位址後面的其他人。位址被拒絕期間,來自它的一切都得到 429,包括有效的金鑰,
  因此能從你的網路送出 10 把錯誤金鑰的人,可以封鎖該位址 5 分鐘。來自其他位址的有效金鑰永遠不受限制。
* 遠端端點除了上述四個工具,還有兩個**被呼叫時會連到被監控伺服器**、且需要 `VIEW SERVER STATE` 的工具
  (`sql/create-readonly-login.sql` 的唯讀登入具備此權限):`get_running_queries`(正在執行的查詢和計畫快取中最耗資源的 15 個陳述式)和
  `get_blocking`(誰阻塞誰,包含閒置但有未結交易的最上游阻塞者)。它們只執行 SELECT,不儲存任何東西。為了保護被監控的伺服器,
  每台伺服器同一時間只執行一個即時讀取(第二個呼叫者 2 秒後會被告知伺服器忙碌),答案會重複使用 3 秒,不論有多少金鑰在問。
  最耗資源的陳述式來自整個 SQL Server 執行個體的計畫快取,所以可能包含與你無關的資料庫的陳述式:限定某一台伺服器的金鑰仍能看到該伺服器上的每個資料庫。
* 限定部分伺服器的金鑰,在任何工具中都看不到其他伺服器,且對看不到的伺服器的錯誤,與對不存在的伺服器相同。已刪除的伺服器會立即從回答中消失。
* **金鑰可以讀取監控資料和執行中查詢的文字,後者可能含有資料。** 每個人或工具各給一把金鑰,不要把金鑰放在共用檔案裡,不再需要時就撤銷。
* 上述 stdio 伺服器不使用金鑰,也從不連到 SQL Server;它只有四個歷史工具。
* 預設憑證是自行簽發的,所以會檢查憑證的用戶端會拒絕它。請用 `--cert` 搭配你的電腦已信任的憑證(例如公司 CA 為這台機器名稱簽發的)。
  自行簽發的憑證是為 `localhost`、機器名稱和完整 DNS 名稱簽發的,所以請用其中之一連線。
  Claude Code 會拒絕自行簽發的憑證,所以請給端點一張你的電腦信任的 CA 簽發的憑證。

### 開啟 Claude Code 的連結

在 Settings > Alerts 開啟 **Add Claude Code links**,Problems 頁面的每個問題旁會多一個「Investigate with Claude Code」連結。
按下去會在新的終端機視窗開啟 Claude Code,並已打好一個問題;按 Enter 之前不會送出任何東西。

* 問題是固定文字,只填入伺服器名稱和問題種類。問題的標題、細節、登入名稱和 SQL 文字絕不會放進去。
* 點連結的人需要在自己的電腦上有 Claude Code 和 SqlLookout MCP(見上),並且至少在那裡的 Claude Code 送出過一則訊息,它的連結處理程式才會註冊。
* 連結只在 Problems 頁面;郵件不帶連結。
