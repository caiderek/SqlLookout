SqlLookout

免費、自架的 SQL Server 監控工具,在 Windows 上執行。它盯著備份、CHECKDB、磁碟、阻塞和死結,有事需要處理時寄 email 通知你。

以 MIT 授權開放原始碼。仍在開發中(0.9.x),有些地方還不夠完善。

下載最新版本 GitHub 原始碼

它做什麼

  • 用唯讀登入,從一台機器連到你的 SQL Server 執行個體,不在被監控的伺服器上安裝任何東西。
  • 設定在網頁上完成:加入伺服器、按 Test,每項檢查會顯示能不能用,或告訴你缺哪個權限。
  • 歷史資料存在本機的 SQLite 檔案,圖表可看 6 小時、24 小時、7 天或 30 天。
  • 有事需要處理時寄 email,需要的話也可發 Teams 訊息。網頁和警示郵件有英文與繁體中文。

它監看什麼

備份與 CHECKDB

最後一次完整備份和最後一次成功的 DBCC CHECKDB 距今多久、suspect pages、資料庫狀態(SUSPECT、OFFLINE、EMERGENCY、RECOVERY_PENDING)。

磁碟與記錄檔

磁碟剩餘空間、磁碟區被填滿的速度、記錄檔使用量、tempdb 空間、Express 容量上限。檔案大小會記錄供歷史查詢。

效能

阻塞(指出源頭阻塞者)、死結、CPU、頁面預期壽命、記憶體授予、使用者連線數、磁碟 I/O 延遲。主要等待事件會記錄下來供歷史查詢。

SQL Agent 作業

上次執行失敗的作業,或執行時間遠超過平均的作業。

Always On、記錄傳送、鏡像

可用性群組的複本與資料移動、記錄傳送的備份與還原時間、被鏡像的資料庫和見證。

登入失敗

從 SQL Server 錯誤記錄計算短時間內的登入失敗(錯誤 18456),列出最頻繁的登入名稱和來源位址。

無法連線

連續連線失敗的伺服器,以及一直失敗或被拒絕的檢查。

每個門檻都可以在 Settings 修改,每個警示群組也可以關閉,單一伺服器也能有自己的門檻。完整清單和預設門檻見 中文 README。

三步開始

  1. 建立唯讀登入。在每台 SQL Server 上,以 sysadmin 執行 sql/create-readonly-login.sql(先改檔案開頭的名稱和密碼)。這個登入只能讀中繼資料和統計資訊。
  2. 執行程式。在監控用的機器上解壓縮,執行 sqllookout.exe web。在那台機器上開啟 https://localhost:8443/,建立管理員帳號。
  3. 加入伺服器。到 Servers > Add a server,填入名稱和登入資訊,按 Test。一分鐘內 Dashboard 就會出現資料。接著在 Settings 設定 email 和 Teams。

要常駐成 Windows 服務,在解壓縮的資料夾雙擊 Setup.cmd。瀏覽器會開啟設定頁,選好資料夾、連接埠和服務帳號後按 Install。之後同一頁也提供升級(Upgrade)和解除安裝(Uninstall)。

安全

  • 監控登入是唯讀的。SqlLookout 絕不寫入你的 SQL Server。
  • 只提供 HTTPS,沒有 HTTP 連接埠。
  • 頁面不含 JavaScript,內容安全政策也禁止它。表單帶有防偽造權杖。
  • SQL 密碼、SMTP 密碼和 Teams webhook 網址以 Windows DPAPI 加密儲存,不再顯示。

常見問題

SqlLookout 會在被監控的 SQL Server 上安裝東西嗎?
不會。它用唯讀登入,從一台機器連到你的 SQL Server 執行個體,不在被監控的伺服器上安裝任何東西。每台伺服器只需要執行一次建立登入的腳本。
它會寫入我的 SQL Server 嗎?
不會。監控登入只能讀中繼資料和統計資訊,不能讀資料表內容,也不能寫入。SqlLookout 絕不寫入你的 SQL Server。
支援哪些 SQL Server 版本?
SQL Server 2008 及更新版本,也支援 Express(Express 沒有 Agent,所以不做作業檢查)。可用性群組檢查需要 SQL Server 2012 以上且啟用 Always On。
監控的歷史資料存在哪裡?
預設存在監控機器資料資料夾裡的 SQLite 檔案。也可以選擇改存在 SQL Server 資料庫。
怎麼收到警示?
用 email,需要的話也可以發到 Teams 聊天或頻道。一個問題會寄一次,持續存在時按重複間隔再寄,惡化時立即寄,解除時再寄一次。每日摘要也兼作服務存活檢查:哪天沒收到,就表示服務停了。
